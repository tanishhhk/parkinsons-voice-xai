1The question and the data

Speaking needs dozens of small muscles in the voice box to work in time. Parkinson's disrupts that fine control, so a person trying to hold one note drifts and wobbles in pitch and loudness. The question: can a model hear that, and can it say why?

The data is the Oxford Parkinson's dataset from the UCI repository: {{dataset.records|int}} recordings of a held vowel from {{dataset.people|int}} people, {{dataset.recordsPerPerson.0|int}} or {{dataset.recordsPerPerson.1|int}} recordings each, all made in one sitting. Each recording comes as {{dataset.featuresBefore|int}} measurements of the voice.

Duplicate measurements removed

31 people or {{dataset.people|int}}?

UCI documents the dataset as 31 people, 23 with Parkinson's. The file's name column holds {{dataset.people|int}} distinct subject IDs, split {{dataset.pd|int}} to {{dataset.healthy|int}}, and that is the only grouping the file supports. If two IDs are the same person, scores here are very slightly optimistic, but grouping by ID is still far more conservative than not grouping at all.

2The flaw: splitting by recording

Most projects on this dataset split the recordings at random. A person's recordings then land on both sides: some in training, one in testing. The model can score well by recognising a voice it has already heard, not by detecting the disease.

The fix is to split by person, so no voice is on both sides. Across {{split.total|int}} models, the random split inflates ROC-AUC per recording by {{split.meanGap|signed3}} on average, and the gap is statistically significant for {{split.significant|int}} of {{split.total|int}}.

The two methods don't even agree on the winner. Random split: {{split.bestLeaky.model|text}} at {{split.bestLeaky.recording|dp3}}. Split by person: {{split.bestHonest.model|text}} at {{split.bestHonest.person|dp3}}, both per recording. Rank correlation between the two orderings: {{split.rankCorr|dp2}}, so choosing a model with the flawed split is close to choosing at random.

4What explainability changed

SHAP splits each prediction into the share each measurement contributed. I expected a tidy chart. Instead it showed that spread1 and PPE, two measures of pitch instability, rank first and second, with the largest shares of the signal. The SHAP values come from a Random Forest, not the benchmark winner. Recomputed across {{explain.stabilitySplits|int}} different splits, only those two keep their place: average rank {{shap[feature=spread1].rankMean|dp1}} and {{shap[feature=PPE].rankMean|dp1}}. Everything below them shuffles.

So I tested them directly, per person, in one matched experiment. spread1 alone scores {{singleFeature[model=spread1].personAuc|dp3}} and PPE alone {{singleFeature[model=PPE].personAuc|dp3}}, against {{singleFeature[model=ALL 16 FEATURES].personAuc|dp3}} for all {{dataset.featuresAfter|int}} features.

One measurement beats all {{dataset.featuresAfter|int}} and varies far less between runs. With so few people, the extra features fit noise. It points towards a small test built on one or two pitch measurements, which this study did not build or test.

5What the voice reveals

The two strongest measurements are about pitch that won't hold still. spread1 tracks how erratically pitch moves; PPE measures irregular pitch control. Both run higher in Parkinson's, with effect sizes of {{biomarkers[feature=spread1].d|dp2}} and {{biomarkers[feature=PPE].d|dp2}}. An effect size (Cohen's d) above 0.8 already counts as large.

The classic measures in most Parkinson's voice papers, jitter (pitch wobble between cycles) and shimmer (loudness wobble), rank below these pitch-stability measures.

"Score alone" is how well the raw measurement separates the two groups, per person, before any model or split.

A screening test is defined by where you set its threshold, not by its accuracy. Each run picks the threshold that catches {{screening.targetSensitivity|pct0}} of cases using its training data only, then freezes it before testing.

8How it was built

The checks that keep the numbers above honest.

  • Grouped splits

    Every split groups by person, so no voice is ever on both sides.

  • Nested tuning

    Each model is tested {{benchmark.0.totalRuns|int}} times ({{protocol.folds|int}} splits, repeated {{protocol.repeats|int}} times). Settings are tuned inside each split, never on test data.

  • Frozen threshold

    The alarm level is chosen on training data, then frozen. Tuning a threshold on the test set is a quiet way to cheat.

  • Scaling in the pipeline

    Scaling is refitted inside each split, so test data never influences training.

  • Duplicates removed

    {{dataset.dropped|len}} near-identical measurements dropped, {{dataset.featuresBefore|int}} became {{dataset.featuresAfter|int}}, so importance isn't split between twins.

  • Explanations on unseen people

    Explaining training data describes memorisation, not real behaviour.

  • Explanations checked for stability

    SHAP was recomputed across {{explain.stabilitySplits|int}} splits. Only measurements that keep their rank count as findings.

  • Accuracy is not the headline

    {{prevalence|pct1}} of recordings are Parkinson's, so a model that always says "Parkinson's" is already {{prevalence|pct1}} accurate.

A common SHAP mistake

For a two-class problem SHAP returns values for both classes, and they mirror each other. Average across the two and they cancel out. Measured on this data, mean importance comes out as shown here.

Any chart built on the average is showing rounding noise. The code documents the fix.

9What this cannot do

Read every figure above with these in mind.

  • {{dataset.people|int}} people is a small sample

    Only {{dataset.healthy|int}} are healthy, so the specificity of {{screening.report.specificity|pct1}} rests on {{dataset.healthy|int}} people. Treat all figures as approximate.

  • One session, one setup

    Nothing here shows it would work with a different microphone, language or clinic.

  • No separate hold-out set

    All results are cross-validation estimates. The dataset is too small to set aside a meaningful final test set.

  • Not early detection

    Everyone in the data already has a diagnosis.

  • Not a medical device

    This is a research and methodology project on a public dataset. Do not use it to make health decisions.
